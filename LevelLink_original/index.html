1시스템 개요

1-1의도

LevelLink는 이미 성장한 카드를 활용해 새로운 카드의 육성을 쉽게 해 주는 도움 시스템입니다.
이미 키운 카드들로 덱을 꾸리면 그 덱의 레벨이 정해지고, 새로 얻은 카드를 등록하면 그 레벨을 그대로 빌려 씁니다.

1-2핵심 개념

개념설명코드
LevelLink (칸)여러 개가 있으며 순서대로 해금한다. 칸마다 덱 구성(슬롯 수, 멤버 조건)과 쿨타임이 테이블로 정해져 있다테이블 LevelLinkList, 서버 LevelLinkList
덱칸마다 최대 7슬롯. 슬롯은 "특정 멤버 전용" 또는 "그룹 전체(아무 멤버)" 조건을 가진다. 이미 성장한 카드를 넣는다테이블 LevelLinkGroupList, 서버 card_1 ~ card_7
LevelLink 레벨덱에 넣은 카드 중 가장 낮은 카드 레벨. 모든 슬롯을 채워야 저장할 수 있다GetLevelLinkSlotLV(), 서버 lv
중앙 슬롯 (등록 카드)새 카드 1장을 등록하면 카드 레벨이 LevelLink 레벨로 적용된다. 원래 레벨이 더 높으면 원래 레벨을 유지한다서버 slot, 카드 level_link_lv
쿨타임등록 카드를 해제하면 그 칸에 쿨타임이 걸린다. 광고 / 보석 / 단축 티켓으로 줄일 수 있다서버 remain_time, 테이블 level_link_cooldown
해금잠긴 칸은 미션 달성 + 골드 + 재료로 연다. 재료가 부족하면 보석으로 살 수 있다PopupLevelLinkUnlock

1-3칸의 상태

LevelLinkManager.GetStateLevelLink()가 서버 데이터로 계산합니다. 판정 순서가 곧 우선순위입니다.

LOCK      (state == 0)        잠김 → 해금 팝업
COOLTIME  (remain_time > 0)   쿨타임 중 → 단축 팝업
SETTING   (slot > 0)          카드 등록됨 → 해제 팝업
EMPTY     (그 외)              비어 있음 → 카드 선택 팝업

1-4카드의 level_link_lv

값의미
0LevelLink가 적용되지 않은 카드. 덱 후보와 등록 후보가 될 수 있다
양수중앙 슬롯에 등록되어 LevelLink 레벨이 적용 중인 카드
-1등록되었지만 원래 카드 레벨이 더 높아 원래 레벨을 쓰는 카드

값이 0인 카드만 덱 후보와 등록 후보가 됩니다.

4UI 프레임워크 (기반 클래스)

LevelLink의 모든 화면은 아래 세 기반 클래스 위에 만들어져 있습니다.

4-1BaseUILayout<TSetting> : 하위 영역

InitUI()                     1회 : 버튼 바인딩, 자식 InitUI
SetData(new Setting{...})    부모가 값 + 콜백(Action)을 넣는다
SetUI()                      setting 값으로 화면을 그린다 (자식에게 Setting을 나눠 주고 자식 SetUI)
UpdateData / UpdateUI        갱신이 필요할 때
  • Setting은 화면 값과 부모에게 돌려보낼 콜백을 함께 담습니다. 자식은 부모를 직접 참조하지 않고 setting.OnClickXXX()를 호출합니다.
  • 기본 메서드는 빈 virtual이고, 부모가 필요한 순서로 호출해 갱신 시점을 직접 정합니다.

4-2CPopupUI<TSetting, TResult> : 결과를 돌려주는 팝업

OpenPopupXXX() → 생성(Awake: subject, result 기본값, Flags) → SetData(Setting)
호출측 : popup.ShowAsObservable().Subscribe(res => ...)   ← 구독해야 열린다
팝업   : 확인 버튼에서 result를 채우고 Close()
닫힘   : OnNext(result) 1회 → OnCompleted
  • 팝업 하나가 "입력 → 결과 1개"인 함수처럼 동작해서, 호출측이 Rx로 다음 단계를 이어 붙일 수 있습니다.

4-3PagePopup : 전체 화면 페이지

  • 팝업 연결 리스트에 들어가지 않고, 결과 스트림이 없습니다. OnClosePopup()으로 파괴합니다.
  • 백키 스택과 페이지 스택에 등록되고, OnStart / OnBackEventProcess로 수명주기를 받습니다.

7서버 API

모든 요청은 LevelLinkService에 있고, LevelLinkManager가 감싸서 호출합니다. 공통 동작은 다음과 같습니다.

  • Cold Observable이라 구독해야 요청이 나갑니다.
  • 응답 코드(e != 0) 안내는 공통 처리가 맡으므로, Do()와 구독자는 성공 응답 처리에 집중합니다.
  • Do()가 구독자보다 먼저 실행되므로, 구독 콜백 시점에는 매니저 데이터가 이미 갱신되어 있습니다.
API매니저 메서드응답 반영성공 후
level_link/topShowLevelLinkPage() 내부칸 목록 + 미션 진행도페이지 생성
level_link/slot_addRequestSlotAdd()칸 목록(해금)LevelLinkUnLockSlot 발행 → 해금 연출
level_link/slot_buyRequestItemBuy() → IObservable<bool>아이템 / 상품 인벤토리해금 팝업 갱신
level_link/deck_saveRequestLevelLinkDeckSave()칸 목록(덱, lv)토스트 + LevelLinkSelectGDID

9핵심 로직

9-1LevelLink 레벨

  • GetLevelLinkSlotLV(slotInfo) = 덱 카드 레벨의 최솟값입니다. 덱을 고르게 키울수록 LevelLink 레벨이 올라갑니다.
  • GetSlotMinCard()는 레벨을 정하는 카드를 찾아 화면에 표시해, 다음에 키울 카드를 알려 줍니다.
  • 덱 저장 전에 IsChangeLevelLinkLowLV()로 레벨 변화를 확인하고, 필요하면 확인 팝업으로 변경 전후 레벨을 보여 줍니다.

9-2카드 후보 규칙

목록메서드제외 조건정렬
덱 편집 카드GetLevelLinkCardDeckList()다른 칸 덱 카드, level_link_lv != 0 → 멤버 필터 → 속성 필터선택한 정렬 전략
자동 배치 후보GetLevelLinkCardDeckAutoList()위와 같음 (현재 칸 덱 카드는 다시 후보)레벨 → 전투력 → 등급 → gdid
중앙 슬롯 등록 후보GetLevelLinkCardIDList()모든 칸 덱 카드(현재 칸 포함), level_link_lv != 0등급 → 레벨 → gdid

덱 카드와 육성 카드(등록 카드)를 서로 겹치지 않게 나눠, "성장한 카드로 덱을 꾸리고, 새 카드를 키운다"는 의도를 규칙으로 보장합니다.

9-3자동 배치 (GetLevelLinkCardDeckAutoList)

1) 후보 = 인벤토리 - 다른 칸 덱 카드 - LevelLink 적용 카드
2) 후보 수 < 슬롯 수 → 배치 불가로 반환
3) 멤버 전용 슬롯 먼저 : 그 멤버 카드 중 우선순위 1등
   - 맞는 카드가 없는 슬롯이 있으면 배치 불가로 반환
4) 그룹 전체 슬롯 : 남은 후보를 우선순위대로 슬롯 수만큼
결과 : Tuple<bool 배치 가능, Dictionary<슬롯, 카드>>
  • 제약이 강한 슬롯(멤버 전용)을 먼저 채워서, 멤버 전용 슬롯에 맞는 카드를 먼저 확보합니다.
  • 호출하는 곳은 두 군데입니다. 페이지에서는 결과가 기존과 다르면 바로 저장하고, 덱 편집 팝업에서는 화면의 배치만 바꿉니다.

9-4정렬과 필터

  • 정렬은 Strategy 패턴입니다. ICardSortStrategy 구현(CardSort_Level / Grade / Power / Name / Recent)을 LevelLinkDeckSort.List에 순서대로 두면 그 순서가 드롭다운 순서가 됩니다. 공통 보조 정렬(card_sort)은 CardSortStrategyBase가 붙입니다(Template Method).
  • 드롭다운 선택 → CurrentDeckSortType.Value 변경 → 덱 편집 팝업이 DistinctUntilChanged().Skip(1)로 구독하다가 목록을 다시 계산합니다.
  • 필터는 "편집 중 선택"과 "적용 선택"을 따로 둡니다. 필터 패널의 확인은 SaveSortInfo(true), 취소는 SaveSortInfo(false)입니다.

9-5쿨타임 타이머

  • TimeStreamManager의 타임스트림을 키 LEVELLINK_SLOT_{칸 ID}로 공유합니다. 중앙 타이머, 하단 슬롯 타이머, 단축 팝업 타이머가 같은 스트림을 구독합니다.
  • 타이머가 끝나면 서버를 다시 부르지 않고 UpdateLevelLinkListData_RemainTime_TimeKey()로 로컬 remain_time을 0으로 맞추고, LevelLinkPageUpdate_CoolTime을 발행합니다.

10설계 패턴 분석

10-1구조 : MVP(Passive View)에 가까운 혼합형

역할클래스근거
ModelLevelLinkManager, CLevelLinkDataManager, LevelLinkService상태, 규칙, 통신
Presenter 역할PageLevelLink, 각 Popup*매니저 값을 읽어 Setting을 만들고, 클릭을 받아 매니저와 팝업을 호출
ViewBaseUILayout 하위 클래스들Setting으로 그리기만 하고, 입력은 콜백으로 위에 보고
화면용 데이터각 Setting값 + 콜백 묶음. ViewModel과 비슷하지만 바인딩은 없음

구조의 특징:

  1. 페이지가 View와 Presenter 역할을 함께 맡습니다. PageLevelLink 한 파일에서 화면 구성과 사용자 흐름을 함께 볼 수 있습니다.
  2. 하위 영역이 필요한 값을 매니저에서 바로 읽습니다. 예: 필터 패널, 중앙 상단, 타이머. Setting을 여러 단계 거쳐 전달하지 않아도 됩니다.
  3. 매니저가 공통 UI 처리를 함께 맡습니다. 토스트, 페이지 로드, 보석 팝업을 매니저가 열어 호출하는 쪽 코드가 짧습니다.
  4. 싱글톤으로 상태를 공유합니다. LevelLinkManager.Instance, CurrentDeckSortType으로 어느 화면에서든 같은 상태를 봅니다.

ReactiveProperty는 세 곳(덱 편집의 CurrentDeckSortType, 해금 팝업의 CPlayer.Gold와 CurrentState)에서 구독하며, 값이 바뀌면 화면 갱신 메서드를 다시 호출합니다.

10-3장점

  • 화면 구조가 프리팹 계층과 그대로 맞아, 화면에서 코드를 찾기 쉽습니다.
  • 하위 영역이 부모를 몰라 재사용하기 쉽습니다. (ObjLevelLinkCard, 쿨타임 타이머는 여러 화면에서 함께 씀)
  • 팝업이 결과 1개를 내는 함수처럼 동작해, 여러 팝업을 거치는 흐름을 Rx로 이어 붙이기 쉽습니다.
  • 서버 결과를 메시지 하나로 모아, 화면 갱신 경로가 한 곳으로 정리됩니다.
  • 매니저 하나에 LevelLink의 상태와 규칙이 모여 있어, 기능 전체를 한 곳에서 파악할 수 있습니다.
